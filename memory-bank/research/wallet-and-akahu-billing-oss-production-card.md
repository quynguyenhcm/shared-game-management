### TRAP Candidates
- Akahu SDK `payments.create/cancel` (token + `from` account) models ENDURING connection payments, not one-off; adopting it for the player flow would force per-player user tokens (contradicts ADR 0016 no-token goal). Easy to mistake for the right API.
- SDK 2.6.0 lacks one-off payment methods and `validateWebhook` is documented around the enduring signature flow (`x-akahu-signature`, `/v1/keys/{id}`) while one-off uses `X-Akahu-Payments-*` headers and `/v1/webhooks/keys/{id}`; reusing the helper unchanged may silently fail verification or use the wrong key endpoint.
- Akahu `status_code` enum above (e.g. `INVALID_ACCOUNT`) comes from the enduring Payment type; mapping it to `teams.payout_blocked_at` (AC-ERROR-4) without confirming one-off `status_reason.code` values risks inventing fixtures.
- One-off webhook has no documented event id and 10s response deadline with 20 retries: non-idempotent handlers or DB work inside the handler can duplicate or time out.
- Blink Node SDK 1.7.4 retry layer retries 4xx and skips 401 refresh (idempotency-key mitigation noted for refunds); fixed status in 1.7.6 not verified.
- No public OSS/production reference for Akahu one-off paying third-party accounts: feasibility rests on vendor docs alone (absence of corroboration, not evidence of failure).

### Open Questions
- Akahu one-off statuses and `status_reason.code` values (Lifecycle page URL 404 on guess): is there a "destination account rejected" code? (Docs lane / sandbox.)
- Does a one-off-capable app require Akahu approval/production access, and are there restrictions on collecting for third-party payees (facilitator rules)? Fees and per-payment/daily limits (docs only say check `GET /v1/connections`).
- Can SDK `validateWebhook` be used for `X-Akahu-Payments-*` webhooks (key endpoint, header name), or must we implement RSA-SHA256 verification ourselves? Key rotation behaviour undocumented.
- Does the sandbox simulate decline, cancel and destination rejection (AC-INTEGRATION-1 fixtures)?
- Blink PayNow: can a platform-held credential pay arbitrary third-party accounts, and what is its webhook signing scheme/status contract? Windcave A2A existence and docs for NZ.
- GitHub commit dates, open-issue counts and release history for both SDKs were not retrievable (no github MCP, WebFetch omitted them).
